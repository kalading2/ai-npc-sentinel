# AI NPC Sentinel — 基于 LangGraph 的 3D 智能 NPC 系统

## 一、项目概述

AI NPC Sentinel 是一个面向企业级 3D 仿真与游戏场景的智能 NPC 系统。通过在 UE5 引擎与本地/云端大模型之间构建标准化的 Agent 编排层，实现了 NPC 从“脚本执行者”到“自主决策者”的跨越。

核心验证目标：
- 3D 环境感知 → 多步推理 → 行为决策的完整闭环
- 企业级私有化部署与数据闭环能力
- 可扩展的 Agent 架构，支持多 NPC、多场景复用

## 三、核心设计思路

### 3.1 分层解耦

系统严格分为三层，层间通过标准化协议通信：

- **表现层 (UE5)**：负责 3D 渲染、物理、动画、感知采集。不关心 AI 如何决策。
- **编排层 (LangGraph Agent)**：负责管理 NPC 的决策流程、记忆、工具调用。不关心 3D 如何渲染。
- **模型层 (阿里百炼/Ollama)**：负责提供 LLM 推理和 Embedding 能力。可替换，不绑定具体厂商。

### 3.2 状态图编排

NPC 的“思考过程”被建模为一个有向图：
\[感知输入]\
│\
▼\
\[意图识别] ──→ chat ──────────────────────┐\
│ │\
├──→ warn/investigate ──→ \[知识检索] │\
│ │ │\
├──→ attack ────────────→ \[威胁评估] │\
│ │ │\
│ ┌─────────┴──┐ │\
│ ▼ ▼ │\
│ \[工具调用] \[行动决策] │\
│ │ │ │\
│ └─────┬──────┘ │\
│ ▼ │\
└──────────────────→ \[行动决策] ←───────┘\
│\
▼\
\[UE 执行]
- 每个节点是独立的异步函数，输入输出通过 `AgentState` 传递
- 条件边根据 `intent` 和 `threat_level` 动态选择路径
- 通过 `MemorySaver` 实现断点恢复和多会话隔离

### 3.3 知识库 RAG 设计

NPC 的行为依据存储在 `guard_rules.txt` 中，通过 RAG 流程注入 LLM 上下文：

1. **启动时**：LlamaIndex 加载文档 → DashScope Embedding 向量化 → 存入 ChromaDB
2. **运行时**：节点主动调用 `retrieve_knowledge(query)` → ChromaDB 语义检索 → 返回相关规则
3. **注入 Prompt**：检索到的规则文本作为 `{rules}` 变量填入 Prompt 模板

架构优势：
- 业务规则与代码分离，策划可直接修改 txt 文件调整 NPC 行为
- 支持热更新（重建索引即可，无需重启服务）
- 可扩展至多文档、多格式（PDF、Markdown、CSV）

### 3.4 MCP 工具调用

Agent 不仅能“说”，还能“做”。通过 MCP 协议，LLM 可以安全地调用 UE 引擎内的 C++ 函数：

- **工具注册**：`tool_registry.py` 定义 6 个工具的 JSON Schema
- **LLM 决策**：`tool_calling` 节点通过 `model.bind_tools()` 让 LLM 自主决定调用哪些工具
- **远程执行**：`mcp_client.py` 通过 HTTP 将调用请求转发给 UE 的 MCP Server
- **结果回传**：UE 执行完毕后返回结果，Agent 将其纳入后续决策

示例工具：`trigger_alarm`（拉响警报）、`draw_weapon`（拔剑）、`move_to_location`（移动）、`lock_gate`（关城门）

### 3.5 记忆系统

| 记忆类型 | 实现 | 生命周期 | 作用 |
|:---|:---|:---|:---|
| 短期记忆 | LangGraph MemorySaver + 窗口截断 | 单次会话 | 记住最近 20 轮对话 |
| 长期记忆 | ChromaDB 向量存储 | 跨会话持久化 | 记住重要事件和玩家特征 |

- 短期记忆通过 `thread_id` 隔离不同 NPC/玩家会话
- 长期记忆在关键事件发生时异步写入，检索时根据语义匹配

### 3.6 性能优化

| 措施 | 效果 |
|:---|:---|
| 节点精简（删除 `response_generation`） | 减少 1 次 LLM 调用 |
| 使用 `qwen-turbo` 模型 | 单次推理从 18s 降至 1s |
| 知识库检索结果缓存 | 避免重复 Embedding 调用 |
| SSE 流式输出 | 对话实时逐字显示，降低感知延迟 |

当前端到端延迟：**3.4 秒**（含知识库检索 + LLM推理 + MCP工具调用）

## 五、关键设计决策

| 决策 | 选择 | 理由 |
|:---|:---|:---|
| LLM 调用方式 | 统一用 `llm_client.ainvoke()` + Prompt 模板 | 保持调用接口一致，不引入 `structured_output` |
| 知识库 Embedding | 阿里百炼 DashScope 原生接口 | 与 LLM 使用同一厂商，简化配置 |
| 向量数据库 | ChromaDB（Demo）/ 预留 Milvus 接口（生产） | Demo 阶段零运维，生产可无缝升级 |
| 工具调用 | MCP 协议 + Function Calling | 标准化、可扩展、LLM 原生支持 |
| 记忆管理 | LangGraph MemorySaver | 原生集成，支持断点恢复和会话隔离 |
| 项目管理 | uv + Python 3.12 | 现代化、快速、依赖锁定 |

## 六、接口文档

### 6.1 `POST /decide`

**请求体**：
```
json
{
  "npc_id": "guard_atto",
  "session_id": "test_001",
  "perception": {
    "player_distance": 150.0,
    "player_visible": true,
    "player_weapon_drawn": true,
    "time_of_day": "night",
    "nearby_allies": 0,
    "alarm_triggered": false,
    "last_player_action": "none"
  }
}
```

**响应体**：
```
json
{
  "npc_animation": "draw_weapon",
  "npc_dialogue": "你他妈站住！老子警告你！",
  "npc_movement": "hold_position",
  "tool_calls": ["trigger_alarm", "draw_weapon"],
  "internal_state": {
    "intent": "attack",
    "threat_level": "high"
  }
}
```

### 6.2 `POST /decide/stream`

SSE 流式接口，实时推送 NPC 对话 token。

### 6.3 `POST /reset/{npc_id}`

重置指定 NPC 的短期记忆。

### 6.4 `GET /tools`

返回当前可用的工具列表。
