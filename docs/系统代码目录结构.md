## 2. 核心文件职责说明

### 2.1 项目根目录文件

| 文件 | 职责 |
|------|------|
| `README.md` | 项目概述、快速启动指南、技术栈说明、架构图 |
| `docker-compose.yml` | 定义 Ollama、ChromaDB、Agent 服务三个容器 |
| `.env` | 全局环境变量：模型名称、端口号、API密钥等 |
| `docs/architecture.md` | 系统架构设计文档，包含Mermaid架构图 |
| `docs/api-spec.md` | 接口规范：请求/响应格式、错误码、MCP工具清单 |
| `docs/npc-design.md` | NPC人设文档：性格、背景故事、行为规则树 |
| `docs/demo-script.md` | 面试演示剧本：6个场景的触发条件和预期表现 |

### 2.2 Agent 后端核心文件

#### main.py — 服务入口
- 创建 FastAPI 应用
- 挂载 API 路由
- 初始化 LangGraph Agent 实例
- 配置 CORS 中间件
- 启动/关闭时的生命周期管理（加载模型、清理资源）

#### config.py — 配置管理
- 从 `.env` 读取所有配置项
- 定义配置类：OllamaConfig、ChromaConfig、AgentConfig、MCPConfig
- 提供全局单例配置对象

#### graph/state.py — 状态定义
- 定义 `AgentState` TypedDict，包含所有状态字段
- 定义 `PerceptionData` 数据类（感知数据模型）
- 定义 `DecisionOutput` 数据类（决策输出模型）

#### graph/builder.py — 图构建器
- `build_agent_graph()` 函数：创建 StateGraph，添加节点，设置边
- `compile_agent()` 函数：编译图并挂载 checkpointer
- 返回编译后的可执行 App

#### graph/nodes/ — 各节点实现

| 节点文件 | 核心函数 | 输入 | 输出 | 调用的外部模块 |
|----------|----------|------|------|----------------|
| `memory_retrieval.py` | `retrieve_memory(state)` | perception_json | conversation_history, long_term_events | memory/short_term.py, memory/long_term.py |
| `intent_recognition.py` | `recognize_intent(state)` | perception + memory | intent | llm/ollama_client.py, llm/prompt_templates.py |
| `threat_assessment.py` | `assess_threat(state)` | intent + memory + rules | threat_level | llm/ollama_client.py, knowledge/retriever.py |
| `knowledge_retrieval.py` | `retrieve_knowledge(state)` | perception + intent | retrieval_result | knowledge/retriever.py |
| `tool_calling.py` | `call_tools(state)` | threat_level + intent | tool_calls, tool_results | tools/mcp_client.py, tools/tool_registry.py |
| `action_decision.py` | `decide_action(state)` | threat_level + tool_results | npc_animation, npc_movement | llm/ollama_client.py |
| `response_generation.py` | `generate_response(state)` | 所有上下文 | npc_dialogue | llm/ollama_client.py, llm/prompt_templates.py |

#### graph/edges/routers.py — 条件路由
- `route_by_threat(state)`：根据威胁等级路由到不同分支
- `route_by_intent(state)`：根据意图路由到闲聊/检索/工具调用
- `should_continue(state)`：判断是否需要继续循环

#### memory/short_term.py — 短期记忆
- 封装 `ConversationSummaryBufferMemory`
- `get_conversation_context()`：获取当前对话上下文
- `add_interaction(user_msg, npc_msg)`：添加一轮交互
- `summarize_memory()`：生成记忆摘要

#### memory/long_term.py — 长期记忆
- 封装 ChromaDB 客户端
- `store_event(npc_id, event_text, metadata)`：存储重要事件
- `retrieve_relevant_events(npc_id, query, k)`：语义检索相关事件
- `format_events_for_prompt(events)`：格式化事件列表为Prompt文本

#### knowledge/indexer.py — 文档索引
- `build_index(document_dir)`：从文档目录构建 LlamaIndex 向量索引
- `persist_index(path)`：持久化索引到磁盘
- `load_index(path)`：从磁盘加载索引

#### knowledge/retriever.py — 知识检索
- `retrieve(query, top_k)`：检索最相关的知识片段
- `format_knowledge_for_prompt(docs)`：格式化为Prompt文本

#### tools/tool_definitions.py — 工具定义
- 定义6个工具的 JSON Schema（名称、描述、参数、返回类型）
- 导出 `TOOL_DEFINITIONS` 列表供 Agent 和 MCP 使用

#### tools/mcp_client.py — MCP客户端
- `MCPClient` 类：管理与UE MCP Server的连接
- `connect(server_url)`：建立连接
- `list_tools()`：获取可用工具列表
- `call_tool(name, arguments)`：调用指定工具
- `disconnect()`：断开连接

#### tools/tool_registry.py — 工具注册表
- `ToolRegistry` 类：管理所有可用工具
- `register_tool(definition, handler)`：注册工具
- `get_tools_for_llm()`：返回LLM可理解的工具列表格式
- `execute_tool(name, args)`：执行工具并返回结果

#### llm/ollama_client.py — Ollama客户端
- 封装 LangChain `ChatOllama`
- `get_llm(model_name, temperature)`：获取LLM实例
- `invoke(prompt, system_prompt)`：同步调用
- `stream(prompt, system_prompt)`：流式调用

#### llm/prompt_templates.py — Prompt模板
- `SYSTEM_PROMPT`：NPC基础人设System Prompt
- `INTENT_RECOGNITION_PROMPT`：意图识别模板
- `THREAT_ASSESSMENT_PROMPT`：威胁评估模板
- `ACTION_DECISION_PROMPT`：行动决策模板
- `RESPONSE_GENERATION_PROMPT`：回复生成模板

#### api/routes.py — API路由
- `POST /decide`：接收感知数据，返回决策结果
- `POST /reset/{npc_id}`：重置指定NPC的记忆
- `GET /health`：健康检查
- `GET /tools`：列出可用工具

#### api/schemas.py — 数据模型
- `PerceptionRequest`：感知请求 Pydantic 模型
- `DecisionResponse`：决策响应 Pydantic 模型
- `ToolCallRecord`：工具调用记录模型
- `ErrorResponse`：错误响应模型

#### storage/decision_logger.py — 决策记录
- `log_decision(session_id, state, output)`：记录完整决策轨迹
- 输出格式：JSON Lines，每行一条完整记录
- 包含字段：时间戳、感知数据、所有节点输出、最终决策、延迟

#### storage/dataset_exporter.py — 数据导出
- `export_to_jsonl(output_path)`：导出训练数据集
- 格式：`{"input": "...", "output": "..."}` 适合微调
- `export_conversation_history(npc_id)`：导出对话历史

### 2.3 UE5 核心文件

#### NPCPerceptionComponent.h/.cpp — 感知组件
- 挂载在NPC Actor上
- `CollectPerceptionData()`：采集7项感知数据
- `SerializeToJson()`：序列化为JSON
- `SendToAgent()`：调用AgentHttpClient发送
- 定时器控制采集频率（0.5秒）

#### NPCActionExecutor.h/.cpp — 行为执行器
- `ExecuteDecision(DecisionResponse)`：解析Agent返回的JSON
- `SetAnimationState(animation)`：驱动动画蓝图
- `SetMovementState(movement)`：驱动AI Controller移动
- `ShowDialogue(text)`：显示头顶气泡
- `ExecuteToolCalls(tool_calls)`：执行本地工具调用

#### AgentHttpClient.h/.cpp — HTTP客户端
- `SendPostRequest(endpoint, json_body, callback)`：通用POST请求
- `SendPerceptionData(json)`：发送感知数据
- `RequestReset(npc_id)`：请求重置记忆
- 异步回调处理

#### MCPServerSubsystem.h/.cpp — MCP服务端
- 继承 `UGameInstanceSubsystem`
- `RegisterTool(ToolDefinition, Handler)`：注册工具
- `HandleToolCall(request)`：处理工具调用请求
- 启动HTTP Server监听Agent的工具调用
- 实现MCP协议的消息解析和响应

#### MCPToolBase.h/.cpp — 工具基类
- 抽象基类，定义工具接口
- `GetToolDefinition()`：返回工具的JSON Schema
- `Execute(parameters)`：执行工具逻辑
- `ValidateParameters(params)`：参数校验

#### 各工具实现文件 — 具体工具
- `TriggerAlarmTool`：触发场景中的警报系统
- `DrawWeaponTool`：控制NPC武器状态
- `MoveToLocationTool`：控制NPC移动
- `InterrogatePlayerTool`：开启盘查对话
- `LockGateTool`：控制城门开关
- `CheckIdentityTool`：查询玩家数据

#### NPCDialogueWidget.h/.cpp — 对话气泡
- UMG Widget，3D空间定位
- `ShowText(text, duration)`：显示文本
- `Hide()`：隐藏气泡
- 自动朝向玩家摄像机

#### DebugPanelWidget.h/.cpp — 调试面板
- 显示当前感知数据
- 显示Agent思考链路（各节点输出）
- 显示工具调用日志
- 显示记忆状态

### 4.3 docker-compose.yml 关键配置
```yaml
version: '3.8'
services:
  ollama:
    image: ollama/ollama:latest
    container_name: sentinel-ollama
    ports:
      - "11434:11434"
    volumes:
      - ./data/ollama:/root/.ollama
    environment:
      - OLLAMA_KEEP_ALIVE=24h
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]

  chromadb:
    image: chromadb/chroma:latest
    container_name: sentinel-chromadb
    ports:
      - "8001:8000"
    volumes:
      - ./data/chroma_db:/chroma/chroma

  agent:
    build:
      context: ./agent
      dockerfile: Dockerfile
    container_name: sentinel-agent
    ports:
````
