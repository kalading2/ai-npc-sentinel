# 3D AI NPC 智能哨兵 — 开发框架与实施计划

## 1. 技术栈选型总览

| 层级 | 技术 | 版本/型号 | 选型理由 |
|------|------|-----------|----------|
| 游戏引擎 | Unreal Engine | 5.4+ | 你现有的核心技能，3D渲染、物理、动画、网络一体化 |
| AI编排框架 | LangGraph | 0.2+ | 图编排管理复杂决策流程，支持checkpointer持久化 |
| LLM集成 | LangChain | 0.3+ | 与LangGraph同生态，提供Memory、Prompt模板等模块 |
| 本地模型推理 | Ollama | 最新稳定版 | 私有化部署，支持Qwen/Llama等主流模型 |
| 推理模型 | Qwen2.5 | 7B-Instruct | 中文能力强，推理速度满足实时交互 |
| 向量数据库 | ChromaDB | 0.5+ | 轻量级，本地部署，适合Demo和小规模应用 |
| 知识检索框架 | LlamaIndex | 0.11+ | 文档索引、检索、RAG一站式方案 |
| 工具调用协议 | MCP (Model Context Protocol) | 最新规范 | 标准化Agent与外部系统交互，面试加分项 |
| 后端框架 | FastAPI | 0.115+ | 高性能异步Python框架，适合AI微服务 |
| 通信协议 | HTTP + SSE | - | 请求-响应用HTTP，流式输出用Server-Sent Events |
| 数据记录 | LangSmith (可选) + 本地JSON | - | LangSmith用于调试可视化，本地JSON作为兜底 |
| 部署 | Docker + Docker Compose | - | 一键启动Ollama + FastAPI + ChromaDB服务栈 |

## 3. 各模块职责与框架映射

### 3.1 UE5 Client 层

| 模块 | 开发语言 | 依赖框架 | 核心职责 |
|------|----------|----------|----------|
| `UNPCPerceptionComponent` | C++ | UE Gameplay框架 | 定时采集7项感知数据，序列化JSON |
| `UNPCActionExecutor` | C++ | 行为树/动画蓝图 | 解析Agent返回的指令，驱动动画状态机、移动、物理交互 |
| `UMCPServerSubsystem` | C++ | UE HTTP Server | 实现MCP协议服务端，注册6个工具函数，处理Agent的工具调用请求 |
| `UAgentHttpClient` | C++ | UE HTTP Module | 封装对Agent服务的HTTP请求，支持异步回调 |
| UI层 | Blueprint | UMG | 头顶气泡对话显示，调试面板展示决策链 |

### 3.2 LangGraph Agent 服务层

| 模块 | 开发语言 | 依赖框架 | 核心职责 |
|------|----------|----------|----------|
| Agent主图 | Python | LangGraph StateGraph | 定义7节点决策图，管理状态流转 |
| 记忆管理 | Python | LangChain Memory | `ConversationSummaryBufferMemory` 管理短期对话，自定义类管理长期记忆 |
| 知识检索 | Python | LlamaIndex | 加载守卫手册文档，构建向量索引，提供RAG检索接口 |
| MCP客户端 | Python | mcp (官方SDK) | 连接UE的MCP Server，注册可用工具列表，执行工具调用 |
| LLM调用 | Python | LangChain ChatOllama | 封装Ollama调用，统一Prompt模板管理 |
| 数据记录 | Python | LangSmith / 本地JSON | 每次决策完整轨迹记录，包含状态、节点输出、工具调用 |
| Web服务 | Python | FastAPI + Uvicorn | 暴露RESTful接口，处理UE请求，返回JSON决策结果 |

### 3.3 数据与模型层

| 模块 | 部署方式 | 核心职责 |
|------|----------|----------|
| Ollama | Docker容器 | 加载Qwen2.5:7B模型，提供本地推理API |
| ChromaDB | Docker容器或嵌入模式 | 存储长期记忆向量和守卫手册文档向量 |
| 文档存储 | 本地文件系统 | 守卫手册txt文档，长期记忆备份JSON |
| 日志存储 | 本地JSON + LangSmith Cloud | 决策轨迹、错误日志、性能指标 |

## 4. 接口契约定义

### 4.1 UE → Agent 请求接口

**接口**：`POST /decide`

**请求体**：
```json
{
  "npc_id": "guard_atto",
  "session_id": "session_001",
  "perception": {
    "player_distance": 450.0,
    "player_visible": true,
    "player_weapon_drawn": true,
    "time_of_day": "night",
    "nearby_allies": 0,
    "alarm_triggered": false,
    "last_player_action": "none"
  }
}
````

**响应体**：

json

复制下载

    {
      "npc_animation": "draw_weapon",
      "npc_dialogue": "站住！放下武器，立即后退！",
      "npc_movement": "hold_position",
      "tool_calls": ["trigger_alarm"],
      "internal_state": {
        "intent": "hostile",
        "threat_level": "high",
        "memory_updated": true
      }
    }

### 4.2 Agent → UE MCP 工具调用

**协议**：MCP标准（JSON-RPC 2.0）

**示例（拉响警报）**：

json

复制下载

    {
      "jsonrpc": "2.0",
      "method": "tools/call",
      "params": {
        "name": "trigger_alarm",
        "arguments": {}
      },
      "id": 1
    }

**目标**：把整个技术栈跑通，确保各组件能正常通信。

| :-------------- | :------- | :-------------------------------------------------- | :-------------- |

| 拉取并测试Ollama模型   | Day 1    | `qwen2.5:7b` 模型就绪                                   | 命令行测试推理正常       |

## 7. 风险与应对

| 风险                 | 影响          | 概率 | 应对方案                            |
| :----------------- | :---------- | :- | :------------------------------ |
| Ollama 7B模型推理延迟>2s | 决策不及时，体验差   | 中  | 降级使用1.8B模型；启用Ollama并发；预加载模型到GPU |
| MCP协议在UE端实现复杂      | 工具调用延期      | 中  | 先用简易HTTP接口替代MCP，后期再迁移           |
| ChromaDB内存占用过高     | 开发机器卡顿      | 低  | 使用ChromaDB的持久化模式，限制缓存大小         |
| 感知数据采集频率过高导致网络拥塞   | Agent请求队列堆积 | 低  | 采用事件驱动上报，只在数据变化超过阈值时发送          |
| LangGraph版本兼容问题    | 代码报错        | 中  | 锁定版本号，使用Docker固化环境              |
